* Verified Facts

- =star-agent= main initially contained the RAGE template, not an executable product. Inspected its tree and root =AGENTS.md= on 2026-10-10 through the GitHub connector.
- [[https://github.com/starintel-labs/star-kb/blob/main/kb/core/star_reasoning.pl][Star-KB reasoning]] exports bounded graph neighbors, paths, document metadata, relation explanations, timelines, contradictions, comparison, evidence sources, reverse references and packets. Its lossless JSON facts live in the =star_json= projection module. It is the *symbolic source of semantics*, not the REPL parser.
- [[https://github.com/lost-rob0t/prolog-rlm/blob/main/docs/direct-runtime.md][prolog-rlm direct]] exports =rlm_direct/4= and a registered-tool runtime with explicit capabilities, bounded futures, authority and an effect journal. Runtime core must remain generic.
- [[https://github.com/lost-rob0t/starintel-pro-actors/blob/main/python/src/starintel_pro_actors/actor_cli.py][pro-actors]] exposes fixed per-actor =sa-*= commands and the =targets.create= contract. Its actor manifests advertise the installed command and service mode. Star Server—not the actor—owns scheduling and leases.
- Star Server's maintained HTTP contract declares =documents.search= at =/api/v1/documents/search= with a required =q= query parameter, and a separate =public.search.get=. The current starintel-client =call()= has no query-param option; a discovered registry-backed GET can bridge this without a new legacy route.
- Star Server's current canonical schema lock inspected 2026-10-10 resolves =release_version= and =schema_version= =0.10.1=. The Star-KB Python projector default in its inspected branch is older, so callers must pass an explicit pinned current release manifest.

* Inference

=star-agent= should own the operator experience and typed adapter ports only. Symbolic facts and proofs come from Star-KB; the direct model may request only host-registered tools, which use the same KB adapter. Named operations and capability validation prevent converting text into executable Prolog, shell or filesystem authority. The CLI should remain useful offline without a model, even when live StarIntel backend services are unconfigured.

* Contradictions

- Treating a Prolog command grammar as a new symbolic "AI engine" would duplicate Star-KB authority. Resolution: the grammar routes to a closed Star-KB query API and explicitly rejects unhandled natural language in symbolic mode.
- The pro-actors manifest output observed in the upstream source can contain historical schema-version fields. It cannot establish authority over the 0.10.1 active lock; real canonical publishing must use the server's locked schema before writing.
- User wishes broad OSINT access, while unrestricted shell and web egress would bypass RLM authority and allow private-network SSRF. Resolution: fixed command names, public HTTP destinations, manifest-bound actors and strict operator allowlists; advanced browser execution belongs to the existing web actor.
- A completed target request is not the same as completed actor work. Only submission receipts may be claimed until downstream job observations arrive.

* Unresolved Questions

- Which Star-KB public rule modules should gain an explicit higher-level symbolic agent/goal-selection predicate in future revisions? The initial slice exposes existing supported predicates.
- When will reward maximizers, Aleph and active learning be approved and merged in Star-KB so Star-Agent can expose them without duplicating semantics?
- Does the deployed server's =documents.search= contract match the generated client manifest and authenticated tenant scope on the target environment?
- Are non-default Prolog RLM providers configured, and does the operator want selected effectful tools in direct mode after a durable effect journal is available?

* Footnotes and Glossary

- *Star-KB* -- the maintained semantic Prolog projection/query library, not a second Star-Agent database.
- *Direct mode* -- prolog-rlm's bounded provider-native registered-tool loop, not a custom planner.
- *Canonical StarIntel document* -- a versioned, validated record admitted by Star Server, not an inferred Prolog solution.
- *Capability* -- a runtime check authorizing a specific named tool; schema registration alone does not grant invocation authority.
