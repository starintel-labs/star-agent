* Design intent

Implement the user-requested REPL without inventing an alternative StarIntel
symbolic AI. The executable composition is:

#+begin_src text
operator input
    |
    v
Star-Agent SWI-Prolog REPL / fixed command grammar
    |
    +--> Star-KB named exported predicates (symbolic, default)
    |          |
    |          +--> trusted canonical projection / provenance
    |
    +--> Python typed side-effect port
    |          +--> SearXNG + bounded public HTTP
    |          +--> starintel-client discovered documents.search
    |          +--> verified pro-actors sa-* CLI -> targets.create
    |          +--> allowlisted dig / whois / subfinder
    |
    +--> prolog-rlm rlm_direct/4 (explicit direct mode)
                   +--> same Star-KB / effect ports through
                        registered RLM tools and authority/effect checks
#+end_src

The REPL owns **only command syntax and named adapter bindings**.
Symbolic claim semantics and graph traversal come from Star-KB. Model data is
never parsed as Prolog source nor converted to host callables. Unknown symbolic
intents fail without an LLM fallback. Every external operation has bounded
input/output, timeouts, structured success/failure and a named capability.

* APIs and safety invariants

- =prolog/star_agent_kb.pl= calls =star_reasoning:tool_*= for named operations and loads a trusted projection through =star_json:load_projection/1=. No general evaluation endpoint.
- =prolog/star_agent_commands.pl= parses REPL intents but contains no competing ontology or inference engine.
- =prolog/star_agent_direct.pl= lazily loads the real prolog-rlm runtime and registers the *same* Star-KB query via =rlm_tool:tool_register/4=.
- =star_agent/effects.py= confines network and subprocess effects. User/model-provided bytes remain argument data, never executable process arguments choosing program names.
- Star Server operations use discovered registry and authorized client/CLI surfaces. A receipt records submission, not completion. No new canonical document writer or schema modification.
- Read capabilities are available in direct mode by default. Effectful model tools require explicit opt-in and the established prolog-rlm durable effect store; no =dangerous= mode is chosen by the adapter.
- Private HTTP destinations, redirects to internal origins, and arbitrary command names are denied. No credential values enter generated files, traces, or version control.
- Add SWI/Star-KB/RLM contract tests and Python offline adapter tests; do not claim live provider or deployed StarIntel end-to-end success from mocks.

* Deferred implementation

Star-KB human-feedback learning, reward maximizers, new symbolic planning
predicates, autonomous recursive target generation, canonical fact promotion,
long-running scheduling, browser interaction and hosted provider integration
require separate owner-specification/contracts and end-to-end verification.
These are *not* covertly reimplemented in Star-Agent.

* Footnotes and Glossary

- *Adapter* -- glue translating a named external tool/command into the existing owner API.
- *Capability* -- granted runtime tool permission, distinct from discovery and authority.
- *Evidence packet* -- Star-KB bundle of bounded neighborhood, timeline, provenance and contradictions.
- *Durable effect journal* -- prolog-rlm service ensuring repeated logical search does not blindly resubmit a remote side effect.
